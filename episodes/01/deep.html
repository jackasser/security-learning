退職した人が、
まだ名簿を見ている。

社員が、顧客名簿のツールをAIで1日で作りました。便利だと喜ばれました。3か月後、退職した田中さんが、まだ名簿を開いていました。なぜ見えるのか。どこを直せば止まるのか。自分で操作して確かめます。

会社も人もデータも架空です。このページは、入力した内容を送信も保存もしません。

1. 正しく使えている状態を見る

あなたは営業の佐藤さんです。ツールの約束は「自分が担当する顧客だけ見える」。101番と102番が担当です。どちらかのボタンを押してください。

問題なく使えます。弱点は、ふつうに使っているだけでは見えません。

2. 何が間違っているかを探す

名簿の中身は、あなたの画面ではなく、離れた場所のコンピューターにあります。これをサーバーと呼びます。画面は「101番をください」と頼み、サーバーが返します。

AIが作ったサーバーの動きを、日本語にするとこうです。

「○番をください」と頼まれたら、
○番の顧客を探して、返す。
足りない確認はどれですか

3. 攻撃する側になってみる

試すのは、この画面の架空のデータだけです。許可のない実在のサービスで同じことをしてはいけません。

あなたは、3か月前に退職した田中さんです。ログインするための登録（アカウント）は止められていません。退職者が入れることに加えて、もう1つ弱点があります。一覧に出るのは、昔の担当の103番だけです。URLの最後の番号を変えて、一覧にない、違う番号の顧客を3件開いてください。番号は101から105です。

一覧にない顧客: 0件 / 3件

4. どこまで広がるかを知る

いまは手で番号を変えました。プログラムを使えば、番号を順に変える作業を自動にできます。番号を知っている必要はありません。

  • 顧客は、未公開の計画や緊急連絡先を知られます。
  • 会社は、調べ、連絡し、説明します。信用も失いかねません。
  • 作った人は、便利にしようとしただけでも、止め方と直し方を求められます。

パスワードを盗む必要も、画面を壊す必要もありませんでした。頼めば返ってきたのです。ただし、同じ弱点でも、会社の外のインターネットから使えるか、何が入っているかで被害の大きさは変わります。

5. 直して、もう一度攻撃する

チェックを1つ入れるたびに、下の4つの結果がどう変わるか見てください。目標は、佐藤さんの仕事は止めず、ほかの3つを止めることです。

入れる対策

なぜ「一覧を隠す」では止まらないのか

隠したのは画面だけです。サーバーへ番号を直接頼めば、返事は変わりません。記録も、止める働きはありません。誰が何を見たかを後で調べるために必要です。

直しても、すでに写し取られた名簿は戻りません。止めた後に、記録を残し、会社の担当者へ知らせます。

6. 自分の職場でやる

試す前に、会社とツールの管理者の許可を取ります。試験用のアカウントと架空のデータを使います。他人のアカウントや実在の顧客番号は使いません。許可がなければ、操作せずに相談してください。

  1. 試験用アカウントAとBを用意し、それぞれ架空の顧客を1件登録します。
  2. Bでログインし、Bの顧客のページを開いてURLを控えます。次にAでログインし直し、そのURLを開きます。顧客の情報が返らなければ合格です。
  3. ログアウトして、同じURLを開きます。情報が返らなければ合格です。
  4. Aのアカウントを止め、Aの顧客を開きます。開けなければ合格です。止める前から開いていた画面でも、読み込み直して確かめます。
  5. Aを戻し、Aの顧客を開けるか確かめます。仕事が止まっていないことも合格の条件です。
  6. 試験用のアカウントとデータを片づけ、結果を管理者へ伝えます。

見えてはいけない情報が見えたら、ほかの番号は試しません。見えた内容を広げず、時刻と操作を記録し、すぐ管理者へ知らせます。

社内ツールの台帳

書いた内容はこの画面だけにあり、閉じると消えます。パスワードや個人情報は書かないでください。

2人で話す

同僚か管理者と話してください。うちの会社で、退職した人のアカウントを止めるのは誰ですか。ツールを作った人が辞めたら、誰が止めますか。

最後に、自分の言葉で

佐藤さんが104番を開くのは、どの対策で止まりましたか。その対策だけでは、田中さんが103番を開けるのはなぜですか。声に出して説明してみてください。

答え合わせ

104番は「その顧客の担当かをサーバーで確かめる」で止まります。103番は田中さんの昔の担当なので、担当の確認は通ります。「退職した人のアカウントを止める」も必要です。

もっと深く

通信と記録では、どう見えるか 
頼みごと   GET /customers/104   利用者: 佐藤
直す前     200          104番の中身を返す
直した後   403または404  中身を返さない

記録には、時刻、利用者、頼まれた番号、許したか断ったかを残します。顧客の中身は記録に書きません。1人が番号を順に開いていたら調べます。

コードでは、どこが違うか 
// 弱い例: 番号だけで探す
customer = find(id)

// 直した例: 本人を確かめ、権限の条件を付けて探す
user = currentUser()   // サーバーが確かめた本人
if (!user || !user.active) return 403
customer = find({ id: id, ownerId: user.id })
if (!customer) return 404

考え方を示す略した例で、そのままは動きません。利用者の情報は、画面から送られた値ではなく、サーバーが確かめたログイン情報から取ります。退職の処理では、アカウントのほか、ログイン中の状態、共有リンク、連携用の鍵も止めます。番号を推測しにくくしても、権限の確認の代わりにはなりません。
